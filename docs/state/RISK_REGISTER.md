# Risk Register

| ID | Risk | Impact | Mitigation / required evidence | Status |
|---|---|---|---|---|
| R-001 | Authorization failure could expose protected source content to retrieval or an LLM. | Confidentiality breach. | Enforce pre-context authorization, fail closed, and add regression tests before any retrieval implementation. | Open |
| R-002 | Retrieved content may contain prompt injection. | Unsafe or ungrounded behavior. | Treat source content as untrusted data; isolate instructions and validate evidence. | Open |
| R-003 | Permission revocation or deletion may leave stale indexed content. | Continued unauthorized access. | Define bounded invalidation behavior and test dynamic revocation/deletion before release. | Open |
| R-004 | Source freshness, authority, and conflicts may produce misleading answers. | Incorrect decisions. | Preserve provenance and timestamps; implement explicit resolution/refusal policy and separate evals. | Open |
| R-005 | Scaffold tooling could be mistaken for completed product assurance. | False confidence. | P03 replaced placeholders with real local gates, but product and infrastructure behavior remain deferred and must not be inferred from scaffold coverage. | Mitigated |
| R-006 | Durable state could drift from implementation. | Incorrect future changes. | Update state and ledgers at every phase checkpoint; promote material decisions to ADRs. | Open |
| R-007 | Exact authorization, cache, deletion, and freshness bounds are not yet selected. | Revocation or deletion could remain effective too slowly. | Freeze measurable bounds during architecture; test next-query behavior, derivative invalidation, and hourly update lag. | Open |
| R-008 | Standards control IDs and evidence tooling depend on the future implementation stack. | Verification could be incomplete or mis-scoped. | P03 pins the local toolchain and records evidence; exact ASVS/SSDF control mapping remains a later implementation task. | Partially mitigated |
| R-009 | Timing and error behavior may reveal protected resource existence even with generic wording. | Confidentiality and privacy leakage. | Define an observable-difference budget and run repeated existing/inaccessible/deleted/nonexistent probes before release. | Open |
| R-010 | OpenFGA scope enumeration, consistency mode, and tuple cardinality may not meet query latency or next-query revocation needs at scale. | Slow queries or stale/incorrect authorization decisions. | Prototype relation model and metadata-first batch checks; measure consistency/latency and run revocation/cross-tenant matrices before schema lock. | Open |
| R-011 | PostgreSQL, OpenSearch, MinIO, and OpenFGA cannot share one atomic transaction for ingestion/deletion. | Partial derivatives, resurrection, stale access, or incomplete deletion. | Define explicit lifecycle state machine, idempotent jobs, tombstones, reconciliation, and failure-injection tests before implementation gate. | Open |
| R-012 | Local models, OpenSearch, Keycloak, and other services may exceed target workstation resources. | Unusable local deployment or pressure to weaken controls. | Benchmark supported local profiles, set resource limits/readiness, and select model artifacts only with evaluation and hardware evidence. | Open |
| R-013 | Ephemeral `npx` Markdown lint is version-observed but not yet a lockfile-pinned development dependency. | Documentation checks may drift when the package is resolved later. | P03 pins `markdownlint-cli2` in `frontend/package-lock.json` and runs it through `npm exec`. | Mitigated |
| R-014 | The full development-tool dependency graph contains a known `lxml 5.4.0` advisory because the current CycloneDX library constrains lxml below 6. | Developer tooling could be exposed to a parser vulnerability or complicate release assurance. | Runtime audits exclude dev-only tooling and pass; replace or isolate the SBOM generator before treating the complete development graph as clean. | Open |
| R-015 | ShellCheck and Trivy are unavailable on the current host. | Host-native release shell/container security checks cannot complete. | `verify-release` now uses pinned local tool containers when host binaries are unavailable; revisit host-native installation if required by operator policy. | Mitigated |
| R-016 | MinIO runs as root in the pinned local image configuration. | Greater impact if the local boundary is misconfigured or a service is compromised. | Keep ports loopback-only and the network internal; evaluate a supported non-root volume posture before production-like use. | Open |
| R-017 | Keycloak development mode and unauthenticated plaintext OpenFGA are unsuitable beyond the local trusted boundary. | Identity or authorization exposure could permit unauthorized access. | Bind to loopback, keep the network internal, document the settings as development-only, and require production-like configuration before deployment claims. | Open |
| R-018 | Pinned infrastructure images and architecture-specific digests may age or lack a manifest for another host architecture. | Startup failure or unreviewed image drift. | Verify manifests during platform updates, retain explicit tags/digests, and keep startup fail-closed on pull/readiness errors. | Open |
| R-019 | The current session revocation store is process-local, so revocation state would not be shared across multiple API workers. | Logout or local revocation could be bypassed by a different worker. | Keep the implementation local-only and single-process for P05; add a durable shared revocation/session store with fail-closed outage behavior before multi-process deployment. | Open |
| R-020 | Keycloak user disablement does not invalidate an already-issued access token in the current local validator. | A disabled user may retain access until token expiry or local revocation. | Keep demo tokens short-lived; add provider user-status or back-channel/session introspection before distributed or production-like use. Test disablement and already-issued-token behavior at that boundary. | Open |
| R-021 | Browser callback and token exchange are implemented as typed helpers but do not yet have a live-browser Playwright flow against Keycloak. | Redirect, cookie, or provider configuration regressions could escape unit coverage. | Reserve authenticated Playwright coverage for the later application-E2E phase; retain PKCE, storage, callback, logout, and malformed-response unit tests in P05. | Open |
| R-022 | OpenFGA model and tuple writes are local bootstrap operations without a product administration workflow or protected operator API. | Unauthorized relationship changes could widen access if the local boundary is exposed. | Keep the service loopback-bound and model/tuple files review-controlled; add authenticated, audited relationship administration and reconciliation before shared deployment. | Open |
| R-023 | The P06 local resource metadata catalog is in-memory and not yet backed by PostgreSQL lifecycle state. | A future implementation could return stale or incomplete tenant/classification metadata around deletion or updates. | Replace the catalog with a fail-closed PostgreSQL adapter and lifecycle transaction/reconciliation before retrieval is implemented. | Open |
| R-024 | OpenFGA `list-objects` enumeration and restricted-resource fine checks may add latency as resource cardinality grows. | Query availability or pressure to weaken current checks. | Measure list/check latency and cardinality, add bounded batching/backpressure, and preserve fail-closed behavior before introducing retrieval-scale scope caching. | Open |
| R-025 | PostgreSQL canonical metadata and OpenFGA/search/object stores remain separate consistency domains. | A partially completed ingestion or deletion can leave metadata and derivatives temporarily inconsistent. | Keep migration and repository transactions explicit; implement idempotent deletion/update reconciliation and failure-injection tests before retrieval release. | Open |
| R-026 | Canonical rows contain references to raw/search data and relationship resources whose external state can drift. | Citations or lifecycle decisions could point at missing, superseded, or stale derivatives. | Validate references during ingestion and evidence resolution, retain tombstones, and add reconciliation metrics and tests in the later pipeline phases. | Open |
| R-027 | Synthetic fixture content or metadata can drift without corresponding hash, ACL, lineage, or golden-case updates. | Evaluation and security conclusions could be based on an incomplete or inconsistent corpus. | `make dataset-validate` checks hashes, deterministic IDs, tenant/ACL/lifecycle/lineage relationships, authority/freshness profiles, required labels, and source types; require it in review and phase gates. | Mitigated |
| R-028 | P08 fixtures are checked in but are not yet loaded through real connectors or the PostgreSQL/OpenSearch ingestion path. | A passing fixture gate does not prove parser, indexing, retrieval, or live authorization behavior. | Keep the out-of-scope boundary explicit in dataset docs/state; require later ingestion and end-to-end evidence before demo or evaluation claims. | Open |
| R-029 | PostgreSQL, MinIO, and OpenFGA writes in P09 cannot share one local transaction. | A failure between raw persistence, canonical metadata, relationship application, and checkpointing can leave temporary partial state. | Use stable identities, explicit write ordering, tombstones, per-item replay, failure-gap cursors, and later reconciliation before retrieval release. | Open |
| R-030 | P09 provides adapters and orchestration but no production worker/bootstrap wiring or live MinIO integration test. | Passing in-memory tests does not prove deployment connectivity, bucket policy, or worker recovery against the local platform. | Add a local worker composition root, service smoke test, and failure-injection integration evidence before claiming end-to-end ingestion. | Open |
| R-031 | Source metadata and ACL fixtures are untrusted inputs at the connector boundary. | A malformed or poisoned source record could influence tenant scope, provenance, or future search eligibility. | Enforce root/type/size/hash/identity/UTC checks, tenant-match validation, dedicated ACL intent mapping, and no body-text policy interpretation; retain P09 regressions. | Mitigated |
| R-032 | P10 parser support is intentionally limited to bounded Markdown-like and JSON source shapes; PDF/Office parsing and safe attachment handling remain future work. | A later parser could introduce active-content, SSRF, decompression, or locator-loss risks. | Keep P10 source-type allowlists and limits; require isolated parser/attachment design, threat-model review, and regression tests before adding new formats. | Open |
| R-033 | The P10 lexical token counter is deterministic but is not the tokenizer used by a future embedding or generation model. | A model-specific limit could be exceeded if later adapters trust only P10 metrics. | Treat P10 counts as an early resource bound; enforce model-adapter token budgets independently and record the tokenizer/version in later index metadata. | Open |
| R-034 | P10 chunks remain an in-memory handoff at the application boundary. | Passing parser tests does not prove canonical persistence and searchable derivative lifecycle are atomically coordinated. | P11 proves disposable indexing and deletion at the OpenSearch boundary; complete canonical tombstone orchestration and pre-context authorization before retrieval claims. | Partially mitigated |
| R-035 | P10 propagates canonical envelope metadata but does not independently reconcile it with PostgreSQL/OpenFGA truth. | A future stale or tampered metadata path could widen search scope if downstream code treats chunk fields as grants. | Use chunk ACL fields only as constraints; re-resolve current OpenFGA authorization before retrieval/context construction and verify canonical metadata lineage. | Open |
| R-036 | A real local semantic model does not by itself establish retrieval quality. | Retrieval quality could be overstated or model replacement could change ranking and evaluation results. | Runtime uses pinned FastEmbed BGE-small ONNX artifacts with explicit model identity/version/dimension and local-only loading; evaluate semantic quality in the separate retrieval evaluation phase. | Open |
| R-037 | Search derivatives and OpenFGA/metadata truth remain separate consistency domains. | An index can contain stale or incomplete metadata around update, revocation, or deletion. | Treat OpenSearch as disposable and non-authoritative; re-resolve current authorization before retrieval/context construction; add live reconciliation and tombstone integration evidence before retrieval release. | Open |
| R-038 | Alias rollback policy and retention/reconciliation across unrelated generations are not yet a full operator workflow. | A live failure could leave stale generations or an alias pointing at an unverified generation. | P11 live tests prove generation creation, alias cutover, and cleanup for isolated generations; add manifest-backed rollback/reconciliation before production-like operation. | Partially mitigated |
| R-039 | The P11 adapter exposes deletion operations but the end-to-end source tombstone cascade is not yet wired through canonical persistence and ingestion workers. | Deleted or de-permissioned content could remain searchable in a live system. | Complete lifecycle orchestration and failure-injection tests before enabling user retrieval; reconcile every generation and alias. | Open |
| R-040 | Existing local PostgreSQL migration state has a checksum drift, so `make up` cannot complete its migration step without an explicit data decision. | Local platform bootstrap is not currently reproducible from the existing volume; silently accepting drift could hide schema divergence. | Preserve the volume, report the drift, and require an approved migration repair or `make reset-demo` before claiming full platform bootstrap. | Open |
| R-041 | The P12 live filtered vector-candidate request reaches local OpenSearch but returns HTTP 400 because the current `nmslib` k-NN mapping does not accept the required filter query shape. | The vector candidate path fails closed, but deployed hybrid retrieval cannot be claimed until filtering and ANN are jointly proven. | In a scoped P12 remediation, select a filter-compatible k-NN engine/query form, preserve mandatory tenant/resource filters and metadata-only source selection, then run the live BM25/vector authorization-filter suite. | Open |
| R-042 | P13R added a production-shaped PostgreSQL/MinIO evidence-content adapter with canonical tenant/chunk/version/lifecycle validation, bounded hash-verified raw reads, and deterministic P10 reconstruction. | The prior missing persistence-backed evidence path is closed; this is not a complete P12/P13 end-to-end proof while R-041 remains open. | Retain the live PostgreSQL/MinIO regression and compose it with future repaired P12/OpenFGA end-to-end evidence; do not bypass canonical integrity checks. | Mitigated |
| R-043 | P13R replaced the lexical runtime reranker baseline with a pinned cache-only local FastEmbed cross-encoder and live adapter acceptance test. | The implementation gap is closed, but broad semantic quality remains unevaluated under R-036. | Keep model revision/cache-only controls and run the separate retrieval/evidence quality evaluation before any relevance-quality claim. | Mitigated |
