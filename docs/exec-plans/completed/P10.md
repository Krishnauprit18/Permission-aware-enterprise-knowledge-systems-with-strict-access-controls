# P10 Parsing, Normalization, Classification, and Chunking Plan

## Status

Complete. This phase implemented the bounded, deterministic content pipeline
between P09 raw source envelopes and future embedding/indexing adapters. It
stops before embedding, OpenSearch indexing, retrieval, reranking, evidence
resolution, and model generation.

## Delivered

- Typed source locators, parsed/normalized document objects, metadata-complete
  chunks, deterministic chunk IDs, bounds, metrics, and conservative
  classification policy.
- Source-aware document/policy/contract sections; Slack parent and nested
  replies; ticket metadata/comments; transcript turn windows; and structured
  hourly records.
- Unicode NFC normalization, malformed UTF-8 replacement, active-content
  handling as data, semantic-first chunking, and bounded line/word fallback.
- Regression coverage for real synthetic fixtures, ACL/classification/version
  propagation, prompt-injection text, empty/huge/malformed content, locators,
  and deterministic identity.

## Security evidence

- Parser branches are selected by canonical source type; source text cannot
  alter authorization or classification.
- Scripts, styles, embedded active blocks, comments, and HTML tags are handled
  as data and are never executed. Macro-looking ordinary text remains text.
- Every chunk carries parent tenant/document/version, account/department,
  classification/shareability, authority, timestamps, and ACL references;
  later authorization remains required before retrieval/model context.
- Independent byte, character, line, token, chunk, thread-depth, and
  transcript-turn limits bound processing. Metrics contain counts only.
