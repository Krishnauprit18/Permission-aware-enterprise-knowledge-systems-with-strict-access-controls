# P03 Phase Prompt

PHASE ID: P03 — Repository Scaffold & Automated Quality Gates.

Implement the repository skeleton and developer quality gates. Do not build product features yet.

Backend requirements:

- modern supported Python version chosen for ecosystem compatibility;
- pyproject-based packaging;
- uv (or documented equivalent) lockfile;
- ruff formatting/linting with security-relevant rules;
- mypy strict (or equally strict static checker);
- pytest with unit/integration markers and coverage thresholds;
- no untyped public business/service APIs unless a documented exception exists;
- dependency vulnerability scanning and secret scanning commands.

Frontend requirements:

- TypeScript strict;
- ESLint + formatting;
- unit test runner;
- Playwright reserved for later E2E;
- package lockfile with reproducible installs;
- no `any` except reviewed/documented boundary adapters.

Repository controls:

- pre-commit hooks;
- editorconfig;
- `.env.example` with fake values only;
- `.gitignore`;
- license/readme as appropriate;
- conventional commits;
- CODEOWNERS-like guidance if useful even for a solo project;
- scripts must use `set -euo pipefail` where applicable;
- shellcheck for shell scripts;
- container/Dockerfile linting.

Security tooling targets:

- SAST (for example Semgrep plus language-native checks);
- SCA/dependency audit;
- secret scanning;
- SBOM generation;
- container/dependency vulnerability scan.

Keep all tools locally runnable; do not require hosted CI.

Implement `make verify` to run the appropriate fast deterministic gates. Separate slower `make verify-release`.

Add architectural tests/import-boundary tests if practical.

Prove the gates work with tests/examples without leaving intentional failures in the tree.

Update engineering docs with exact commands, expected runtime class (fast/slow), and failure triage.

Finish with self-review + state/prompt ledgers + gate report.
