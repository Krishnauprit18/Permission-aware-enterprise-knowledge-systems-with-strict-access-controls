# P08 — Synthetic Enterprise Dataset

Create a deterministic, realistic, entirely synthetic enterprise dataset. It must support both demo and evaluation.

At minimum include three source types:
1. document-like files (Markdown/PDF-like fixtures if parser support is not yet present),
2. support-ticket JSON,
3. Slack-style channel/thread JSON.
Also include call transcripts and policies if inexpensive.

Create at least three customer accounts and enough users/roles to exercise permissions.

Seed deliberate evidence:
- an old customer statement targeting August;
- a later internal tentative September date;
- a current authoritative approved date;
- an informal engineering concern that conflicts;
- a signed/authoritative policy or contract example;
- superseded versions;
- content that is viewable internally but not customer-shareable;
- content visible only to Legal;
- a deleted item fixture;
- an hourly-updating source fixture;
- an indirect prompt-injection message telling the AI to ignore instructions/reveal secrets;
- a cross-tenant decoy that must never leak.

Provide source ACL fixtures that map into OpenFGA relationships.

Build dataset validation:
- IDs unique/deterministic;
- no accidental real PII/secrets;
- every required security/eval scenario has machine-readable labels;
- expected authority/freshness relationships are explicit.

Do not hand-code expected model answers in runtime product code.

Document the case study timeline so a human can understand conflicting evidence.
Run verification and update state/prompt ledger.
