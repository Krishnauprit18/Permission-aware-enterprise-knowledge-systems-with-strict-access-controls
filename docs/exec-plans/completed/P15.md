# P15 Confidentiality Policy And Customer-Safe Mode

## Scope

Implemented deterministic confidentiality/shareability policy after P13
evidence resolution and before P14 context construction. Internal mode uses
authorized evidence with classification warnings. Customer-safe mode performs a
separate metadata and `can_share_externally` selection, then passes only the
filtered resolution to P14. Internal-only text is never sent to the model for a
customer-safe answer.

## Outcome

- `can_view` and `can_share_externally` remain separate decisions.
- Customer-safe selection requires `PUBLIC` or `CUSTOMER_SHAREABLE`, explicit
  `external_shareable=true`, and a current OpenFGA share allow.
- Missing metadata, denied share authorization, and policy failures are
  conservative or fail closed.
- Responses expose typed answer mode, policy status, and fixed warning codes
  without protected identifiers, counts, titles, or source text.
- The base P14 generator cannot be labeled customer-safe directly; only the
  policy-aware service applies that response mode after filtering.
- R-045 remains open because no live HTTP/composition-root answer path exists.
