# P17 Auditability And Observability

## Scope

Implement structured, redacted observability and security auditability across
the protected query and ingestion paths. Connect existing minimized trace
contracts to durable local persistence and the local OpenTelemetry collector.
Do not add product retrieval, generation, or authorization behavior.

## Exit gate

- Per-query audit records capture safe request, principal, authorization,
  retrieval, evidence, generation, policy, latency, and outcome metadata.
- Security events cover authentication, authorization denial, relationship and
  lifecycle changes, policy changes, and administrative actions through a typed
  redacted sink.
- OpenTelemetry spans and bounded metrics correlate API, query, and ingestion
  stages with local Jaeger/Prometheus.
- Tokens, cookies, secrets, vectors, raw confidential text, and hidden model
  reasoning are rejected by redaction tests.
- Observability outage cannot widen authorization or crash a protected request
  unexpectedly; the documented audit durability policy is explicit.
- Fast and applicable release gates pass; state ledgers and prompt archive are
  updated before the checkpoint commits.

## Verification

- Unit tests for redaction, trace construction, span correlation, safe failure,
  and audit event categories.
- Integration tests for migration/repository persistence where local PostgreSQL
  is available, plus collector/trace endpoint smoke evidence when the platform
  is running.
- Full `make verify` and `make verify-release` checks.
