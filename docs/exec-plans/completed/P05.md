# P05: Identity and Authentication

## Objective

Implement local Keycloak/OIDC authentication without introducing authorization
logic or product retrieval workflows.

## Scope

- Add a deterministic Keycloak realm, public browser client, groups, and
  synthetic users.
- Add local bootstrap for generated demo-user credentials without committing
  credential values.
- Add a typed backend principal and OIDC access-token validation boundary.
- Add browser Authorization Code + PKCE helpers with in-memory access-token
  storage only.
- Add generic authentication errors, correlation IDs, logout/session
  revocation behavior, and redacted structured auth diagnostics.
- Add focused authentication and security regression tests.
- Update the threat model, ASVS references, operations guidance, and durable
  state.

## Security decisions

- The browser uses a public Keycloak client with S256 PKCE.
- The frontend never writes access or ID tokens to Web Storage; only transient
  PKCE state and verifier values use session storage.
- The API validates issuer, audience, signature, expiry, not-before, issued-at,
  required claims, algorithm, and bounded clock skew.
- Client claims identify a validated principal but do not grant resource access;
  authorization remains a later server-side OpenFGA/application decision.
- Logout revokes the validated session handle in the local process and clears
  browser memory. A future durable session store must preserve the same
  fail-closed contract.

## Exit gate

- Focused auth tests and all applicable `make verify` checks pass.
- Realm/bootstrap configuration contains no real or generated secrets.
- Token values, cookies, authorization headers, and passwords are absent from
  logs and test output.
