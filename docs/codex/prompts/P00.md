# Sanitized Phase Prompt: P00

```text
You are the implementation engineer for a product-grade, local-only Permission-Aware Enterprise Knowledge System.

PHASE ID: P00 — Bootstrap the Engineering Constitution.

Hard constraints:
- Work only on P00. Do not implement product features yet.
- This project is local/on-prem style; no cloud infrastructure is required.
- Security is shift-left from the first line of code.
- The source idea requires: >=3 heterogeneous enterprise sources; parsing/chunking; metadata including source/account/department/timestamp/access level; user authentication; permission-filtered retrieval; hybrid search; reranking; cited grounded answers; traces; >=50-question golden dataset; separate retrieval/generation evaluation; conflicts/staleness/refusals; and a realistic dynamic permission/update constraint.
- Unauthorized chunks MUST NOT be sent to the LLM. Post-generation filtering is never an authorization mechanism.
- Never rely on model memory as durable project state.

First inspect the current repository. Then create the project operating system:
1. Root AGENTS.md must stay compact and act as a table of contents/constitution, not an encyclopedia.
2. Create structured docs:
   - docs/00-product/
   - docs/01-architecture/
   - docs/02-security/
   - docs/03-engineering/
   - docs/04-evals/
   - docs/05-operations/
   - docs/decisions/
   - docs/exec-plans/active/
   - docs/exec-plans/completed/
   - docs/state/
   - docs/codex/prompts/
3. Add source-of-truth files:
   - docs/state/CURRENT_STATE.md
   - docs/state/TASK_LEDGER.md
   - docs/state/PROMPT_LEDGER.md
   - docs/state/TEST_STATUS.md
   - docs/state/RISK_REGISTER.md
4. Add templates for ADRs, phase plans, security findings, test evidence, and release evidence.
5. Define mandatory engineering rules:
   - typed code; strict linting/type checking;
   - tests are required with implementation;
   - no secrets in repo/logs;
   - dependency pinning/lockfiles;
   - secure defaults, deny-by-default authorization;
   - structured logging with redaction;
   - migrations for schema changes;
   - no silent exception swallowing;
   - deterministic/citable evidence flow;
   - no security decision delegated to an LLM;
   - no merge/phase completion with failing required checks.
6. Add a Makefile (or equivalent simple task runner) with placeholder targets: bootstrap, fmt, lint, typecheck, test, test-unit, test-integration, test-security, sbom, scan, verify, up, down, reset-demo, seed-demo.
7. Define a commit convention and phase checkpoint convention.
8. Create docs/codex/PERSISTENCE_PROTOCOL.md:
   - exact prompts are stored once under docs/codex/prompts/PXX.md after secret sanitization;
   - PROMPT_LEDGER stores short summaries + hashes + outcome + commit;
   - future phases read AGENTS.md + CURRENT_STATE.md + the active phase plan + only relevant design docs; they do NOT reread all historical prompts;
   - all decisions that matter are promoted into ADR/design docs, so historical chat is never required.
9. Create docs/03-engineering/QUALITY_GATES.md aligned to shift-left secure SDLC.
10. Do not claim compliance certification. Define "aligned to / verified against" standards only.

At phase end:
- run every applicable check;
- self-review the diff for security, correctness, maintainability, unnecessary complexity, and violations of AGENTS.md;
- update CURRENT_STATE, TASK_LEDGER, TEST_STATUS, RISK_REGISTER, and PROMPT_LEDGER;
- save a sanitized copy of this phase prompt to docs/codex/prompts/P00.md;
- report: files changed, commands/tests run, evidence, remaining risks, and exact gate status.
```
