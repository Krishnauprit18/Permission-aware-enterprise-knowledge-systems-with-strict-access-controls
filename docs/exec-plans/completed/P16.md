# P16 Product API And Web UI

## Scope

Expose a versioned, typed product API over the existing authentication and
grounded-answer contracts, then build the React evidence-first user interface.
The API owns validation, authentication, policy-aware service invocation,
structured errors, and safe response projection. The browser owns presentation
only and never receives infrastructure credentials or authorization authority.

## Exit gate

- API request/response contracts are bounded, OpenAPI-visible, and covered by
  contract/security tests.
- Security headers and generic error envelopes are applied by the API boundary.
- UI renders answer claims, backend citations, policy warnings, conflict and
  freshness indicators, refusal states, and trace IDs without HTML injection or
  chain-of-thought.
- Internal and customer-safe mode are distinct request values; mode does not
  bypass backend authentication or confidentiality policy.
- Frontend unit tests and a Playwright contract flow cover login-state query,
  citations, permission-specific responses, customer-safe mode, and XSS-safe
  rendering.
- `make verify` and applicable release checks pass; state ledgers and prompt
  archive are updated before checkpoint commits.

## Explicit boundary

The API composition root remains adapter-injected. It must not invent answers,
trust browser filters, or silently use an unconfigured search/model stack. A
missing production query service returns a generic unavailable response. Full
live P12-P15 service wiring is tracked separately and is not replaced by a UI
fixture.
