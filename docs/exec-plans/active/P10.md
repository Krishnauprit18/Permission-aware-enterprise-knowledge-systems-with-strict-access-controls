# P10 Parsing, Normalization, Classification, and Chunking Plan

## Scope

Implement the bounded, deterministic content pipeline between P09 raw source
envelopes and future embedding/indexing adapters. The pipeline will parse the
synthetic document, Slack, ticket, transcript, policy, and contract shapes;
normalize Unicode and active content as data; apply deterministic
classification policy; and emit metadata-complete chunks with citation
locators and metrics.

## Out of scope

P10 does not embed, index, search, rerank, resolve evidence, call a model,
change PostgreSQL schema, or make an authorization decision. No source text is
treated as an instruction or access-control authority.

## Exit evidence

- Typed domain models and parser/normalizer/chunker ports are implemented.
- Source-aware fixtures and regression tests cover bounded input, malformed
  Unicode, active content, nested threads, metadata/ACL propagation,
  versioned identity, prompt-injection text, and locator reconstruction.
- `make verify` and `make verify-release` pass, with the documented local
  integration skips if the private database is not exposed.
- Architecture/security docs, state ledgers, the sanitized prompt archive,
  and this plan are updated before the checkpoint commit.
