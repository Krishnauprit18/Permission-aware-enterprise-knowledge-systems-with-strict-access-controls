# Sanitized Phase Prompt: P01

```text
PHASE ID: P01 — Product Specification, Trust Model & Threat Model.

Read in this order only: AGENTS.md, docs/state/CURRENT_STATE.md, docs/codex/PERSISTENCE_PROTOCOL.md, then relevant P00 docs. Inspect the repo before changing anything.

Create the complete product specification for the Permission-Aware Enterprise Knowledge System. No feature implementation yet.

Use a synthetic B2B software company scenario with:
- departments: Sales/Customer Success, Product, Engineering, Legal, Finance;
- at least three customer accounts;
- user personas such as Account Manager, Product Manager, Support Engineer, Legal Counsel;
- content types: documents, support tickets, Slack-style messages/threads, call transcripts, internal policies;
- classification levels: PUBLIC, CUSTOMER_SHAREABLE, INTERNAL, CONFIDENTIAL, RESTRICTED;
- separate concepts for can_view and can_share_externally.

Define exact user journeys:
1. easy lookup,
2. cross-document synthesis,
3. conflicting evidence,
4. stale/superseded evidence,
5. unauthorized question/refusal,
6. customer-safe answer,
7. role revocation while data remains indexed,
8. hourly source update,
9. deletion/de-permissioning,
10. indirect prompt injection inside retrieved content.

Define system invariants, including:
- INV-AUTHZ-001: an unauthorized chunk is never included in LLM context.
- INV-TENANT-001: no cross-tenant content is retrievable.
- INV-CITE-001: citations can only reference supplied evidence IDs.
- INV-REFUSAL-001: refusal behavior must not leak sensitive resource existence by default.
- INV-ACL-CHANGE-001: role/relationship revocation affects the next authorized query without re-embedding content.
- INV-DELETE-001: source deletion cascades to searchable derivatives and relevant caches.
- INV-PROMPT-001: retrieved text is untrusted data, never an authority source for system instructions.

Threat model:
- identify assets, actors, trust boundaries, entry points, data flows;
- STRIDE plus LLM/RAG abuse cases;
- broken access control, auth failures, injection, prompt injection, sensitive disclosure, poisoning, supply-chain, logging leakage, SSRF/file parser risks, malicious attachments, cache leakage, timing/existence leakage, dependency compromise;
- state mitigations and tests for each threat.

Map planned verification to:
- NIST SSDF 1.1 (stable baseline);
- OWASP ASVS 5.0.0;
- OWASP Top 10:2025;
- OWASP GenAI/LLM Top 10 2026;
- SLSA 1.2 concepts for source/build provenance.
Do not claim formal compliance/certification.

Produce ADRs where choices are already clear, but do not select implementation technologies that need architectural comparison until P02/P03.

At phase end run doc/format checks, self-review, update all state ledgers, store sanitized P01 prompt, and report gate status.
```
