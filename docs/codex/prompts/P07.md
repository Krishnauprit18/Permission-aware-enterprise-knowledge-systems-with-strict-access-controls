PHASE ID: P07 — Canonical Data Model & Persistence.

Implement canonical domain models and PostgreSQL persistence.

Required entities:
- users/principal references (do not duplicate identity secrets)
- tenants
- accounts
- source_connections
- source_items/documents
- document_versions
- chunks (metadata/reference; searchable payload may live in OpenSearch)
- ingestion_jobs/checkpoints
- deletion tombstones
- query_traces metadata
- evaluation datasets/cases/runs or a clean persistence boundary for them

Document metadata must support at minimum:
source_type, source_external_id, source_url, tenant_id, account_ids, department,
created_at, updated_at, author, classification, external_shareable,
authority_level, ACL relationship references, version, content_hash, language,
status/deleted, supersedes/lineage where known.

Chunk identity must be deterministic/stable enough for re-ingestion and citation reconstruction.

Requirements:
- schema migrations only; no runtime auto-create;
- appropriate unique constraints/FKs/indexes;
- UTC timestamps;
- no raw secrets;
- no authorization decision encoded solely as stale denormalized DB flags;
- soft/tombstone vs hard-delete policy documented;
- retention policy fields where useful.

Add repository/service layer with typed domain objects and transaction boundaries.
Test migration from empty DB, idempotent seed behavior, integrity constraints,
versioning, and deletion markers.

Generate/update docs/generated/db-schema.md from the real schema if practical.
Run verification; update state/prompt archive.
