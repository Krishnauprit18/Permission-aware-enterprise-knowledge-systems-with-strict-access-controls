# Sanitized Phase Prompt: P02

```text
PHASE ID: P02 — Architecture & Technology Decisions.

Read AGENTS.md, CURRENT_STATE.md, active phase plan, product spec, threat model, and ADR index. Do not reread unrelated history.

Design and document the reference architecture. Prefer this local-first stack unless repository evidence justifies a better choice:
- Backend: Python + FastAPI, strict typing.
- Frontend: React + TypeScript (strict) with a small maintainable toolchain.
- PostgreSQL: operational/control metadata.
- OpenSearch: BM25 + vector/hybrid retrieval + metadata filtering.
- OpenFGA: relationship-based/fine-grained authorization.
- Keycloak: local OIDC identity provider.
- MinIO: raw object storage.
- Redis only where justified for queue/cache; do not introduce it by default without a use.
- Local worker process for ingestion jobs.
- OpenTelemetry for traces/metrics/log correlation.
- Local model adapters: an LLM interface, embedding interface, and reranker interface. Default implementations must be runnable locally; model names are configuration, not hard-coded business logic.
- Docker Compose for all infrastructure and local deployment. No Kubernetes/cloud work.

Architect mandatory pipelines:
A. ingestion: connector -> raw store -> parse -> normalize -> ACL map -> classify -> chunk -> embed -> index -> checkpoint.
B. query: authenticate -> resolve authorization scope -> permission-constrained hybrid retrieval -> rerank -> evidence resolution -> context construction -> LLM -> citation validation -> policy warning -> response -> audit trace.
C. deletion/change: detect -> remove/tombstone derivatives -> invalidate cache -> remove auth relation -> audit.
D. role change: auth relationship update -> next query sees new scope; no re-embedding.

Design authorization so dynamic revocation works:
- OpenFGA is source of relationship truth.
- At query time resolve allowed objects/scopes before model context construction.
- Search filters are server-generated and intersected with semantic/user filters.
- Never trust client-supplied ACL filters.
- Any coarse-filter + fine-check design must guarantee unauthorized text is not included in the context builder.

Define interfaces/protocols for connectors, parser, chunker, embedder, search backend, authorization service, reranker, LLM, evidence resolver, audit sink.
Define versioning for index schema, embeddings, prompts, evaluation dataset, and API.

Create ADRs with alternatives and rationale, including why OpenSearch instead of a vector-only DB, why OpenFGA, why Keycloak, why Docker Compose, and why local model adapters.

Create dependency boundaries and import rules to prevent framework spaghetti. Use ports/adapters or similarly clear layering without overengineering.

At phase end: architecture lint/review, update ledgers, save prompt, and report gate status. No business feature implementation yet except tiny interface skeletons only if needed to validate architecture.
```
