# P07: Canonical Data Model and Persistence

## Objective

Implement the canonical PostgreSQL control-data model and a typed repository
boundary for lifecycle, source, ingestion, trace, and evaluation metadata.
Keep raw content, embeddings, relationship truth, and identity secrets outside
this schema's authority boundaries.

## Scope

- Add the ordered PostgreSQL migration and explicit migration runner.
- Model tenants, principal references, accounts, source connections, source
  items, document versions, chunk metadata, jobs/checkpoints, deletion
  tombstones, query trace metadata, and evaluation metadata.
- Add UTC-aware typed domain objects and a transaction-scoped repository/UoW.
- Enforce deterministic document-version/chunk identity inputs, lifecycle,
  lineage, retention, foreign-key, and uniqueness constraints.
- Add migration, integrity, idempotency, versioning, and deletion-marker tests.
- Document generated schema, retention/delete policy, and operational commands.

## Security decisions

- No identity credential, bearer token, authorization decision, or searchable
  chunk text is stored in PostgreSQL.
- OpenFGA remains the relationship decision source. Database metadata can
  describe resource lifecycle and relationship references but cannot grant
  access through stale denormalized flags.
- Source deletion is represented by a durable tombstone and a deleted lifecycle
  state; derivatives are removed by the deletion pipeline and tombstone
  retention prevents stale replay from resurrecting content.
- Runtime code never auto-creates or mutates schema structure. Migrations are
  explicit, ordered, checksum-verified, and fail closed on drift.

## Exit gate

- Empty-database migration succeeds and is idempotent with checksum validation.
- Typed repository operations commit and roll back within explicit boundaries.
- Integrity constraints cover tenant ownership, source identity, versions,
  stable chunk identity, lifecycle, and deletion markers.
- Focused unit/integration/security checks pass with no raw secrets or product
  retrieval implementation.
- Generated schema documentation, state ledgers, prompt archive, and risks are
  updated; this plan is complete.
