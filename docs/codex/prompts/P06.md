PHASE ID: P06 — Fine-Grained Authorization with OpenFGA.

Implement authorization as a first-class service using OpenFGA.

Model:
- tenant/organization
- group membership
- customer account membership/management
- departments
- documents/resources
- direct viewer/owner relationships
- inherited account/project access where appropriate
- explicit restricted/legal access
- can_view
- optionally a separate policy path for can_share_externally (classification metadata may also participate)

Principles:
- deny by default;
- backend is policy enforcement point;
- OpenFGA is relationship decision source;
- LLM never participates in authorization;
- client filters never grant access;
- authorizer errors/timeouts fail closed for protected content.

Implement:
- typed authorization port + OpenFGA adapter;
- check(user, relation, object);
- list authorized resource IDs/scopes needed for permission-first search;
- deterministic synthetic tuple seeding;
- authorization decision audit fields without exposing sensitive graph details;
- authorization decision/fingerprint versioning strategy for safe cache invalidation later.

Tests must cover:
- same user, allowed account;
- cross-account denial;
- restricted department denial;
- direct grant;
- group grant;
- revoked relation effective on next request;
- unknown resource denied;
- FGA unavailable -> protected request fails closed;
- tenant isolation.

Create a permission matrix fixture suitable for later golden evaluations.

Do not implement retrieval yet. Update docs/ADRs/state/prompt ledger and run verification.
