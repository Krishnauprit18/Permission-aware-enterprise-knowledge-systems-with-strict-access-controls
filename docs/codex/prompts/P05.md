# Sanitized Phase Prompt: P05

```markdown
PHASE ID: P05 — Identity & Authentication.

Implement authentication with local Keycloak/OIDC.

Create deterministic demo realm/bootstrap configuration with synthetic users and groups. Do not put real secrets in repo.

Security requirements:
- use Authorization Code + PKCE for browser flow or a secure BFF/session architecture documented by ADR;
- do not store bearer/access tokens in localStorage;
- secure/HttpOnly/SameSite cookie settings where cookies are used;
- issuer, audience, signature, expiry, not-before, and algorithm validation;
- explicit clock-skew policy;
- CSRF defense where state-changing cookie-authenticated endpoints exist;
- logout/session invalidation behavior;
- rate limiting strategy documented for auth-sensitive routes;
- generic auth errors to clients; detailed safe diagnostics to structured logs;
- correlation IDs without token logging.

Create principal abstraction in backend: subject ID, tenant ID, groups/claims, but do not make authorization decisions from untrusted client data.

Tests:
- happy login;
- missing token;
- expired token;
- wrong issuer/audience;
- tampered token;
- disabled user;
- group claim parsing;
- logging redaction;
- session/logout flow.

Add auth-specific threat-model updates and ASVS verification references where useful.
Run all quality/security checks, update state, archive prompt.
```
