PHASE ID: P12 — Permission-First Hybrid Retrieval.

This is a security-critical phase. Implement the query retrieval pipeline up to candidate results, not LLM generation.

Flow:
authenticated Principal
-> authorization service resolves allowed tenant/resources/scopes at query time
-> server constructs immutable authorization filter
-> optional semantic/account/date filters are INTERSECTED with authorization filter
-> BM25 search + vector search inside authorized scope
-> rank fusion (RRF or documented equivalent)
-> candidates returned with provenance and authorization evidence/fingerprint.

Critical invariant:
NO unauthorized chunk may be passed beyond the authorization boundary toward reranking/context generation. It is not acceptable to retrieve broadly and depend on the LLM/output filter.

If OpenFGA ListObjects or equivalent allowed-resource enumeration is used, document performance limits and keep an interface for future scalable authorization-aware filtering.

Controls:
- deny on authz service failure;
- tenant filter is mandatory;
- never trust account/document IDs from client as granting filters;
- prevent filter injection;
- cap result sizes/query length;
- explicit timeout budgets;
- no sensitive existence disclosure in user-facing errors.

Hybrid retrieval:
- implement BM25 and vector candidate paths;
- RRF/fusion configurable and deterministic;
- collect component rank/score diagnostics in internal trace only.

Tests MUST include:
- same query under three different users returns different authorized candidate sets;
- cross-account/cross-tenant decoys never appear;
- Legal-only chunks never appear for Account Manager;
- role revocation changes the next query without re-embedding;
- authorization failure/timeout fails closed;
- malicious client-supplied filter cannot widen access;
- zero Unauthorized Context Rate on fixture corpus.

Add retrieval evaluation hooks now, even before full golden dataset.
